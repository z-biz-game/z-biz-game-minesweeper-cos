# 扫雷 · Minesweeper（零猜测版）

> *数字是雷数，不是提示。每一局都在出题时被求解器跑过一遍，推到底的那一步一定存在。*

浏览器原生的 **扫雷**：无构建步骤、无打包器、**零美术与音频文件**——棋盘、旗子、雷、爆炸全部由
canvas 现画，音效由 WebAudio 合成，界面只有一个 `<canvas>`。

- **核心承诺**：生成的每一局都保证 **从开局那一格出发，只用铅笔逻辑就能翻开所有安全格**，
  不存在"五五开"。这不是文案，是准入门槛——求解器推不到底的候选盘直接丢弃。
- 难度不是标签：`新兵 → 突击队` 五档的分数带由求解器**实测**得出（`npm run balance` 打印分位表），
  `generate.js` 里的分档表照那张表写，测试再盯着那张表不漂移。
- 提示不是答案：提示跑的是**同一个**求解器，所以它必须说出用了哪条规则、钉在哪一格；
  你插错的旗它也会指出来并替你拔掉，而不是假装没看见。
- 规模：10 个 ES Module / 2,538 行 JS + 8 个验证脚本 / 2,136 行 + 389 行 CSS/HTML，**运行时依赖 0 个**。
- **在线试玩**：<https://z-biz-game.github.io/z-biz-game-minesweeper-cos/>（`main` 分支推送即自动部署）

```bash
npm start            # 零依赖静态服务 → http://127.0.0.1:5173
npm run electron     # 桌面壳（electron/main.cjs，同一份代码）
```

```bash
npm run check        # 逐文件 node --check 语法门禁
npm test             # 引擎断言 167 项：求解器可靠性 / 生成保证 / 规则 / 存档形状
```

## 玩法

| 操作 | 行为 |
|---|---|
| 左键按下 | 挖开；挖到 0 自动开花一整片。**已经插旗的格会拒绝**，不会一指尖撞翻自己的判断 |
| 左键点数字 | 和弦：旗数正好等于数字 ⇒ 周围剩余格全开；旗多了拒绝、旗少了也拒绝 |
| 右键 | 插旗 / 拔旗 |
| 中键 / Shift+点 | 清掉标记回到未挖——**唯一绝不会插旗的动作** |
| 触屏 | 轻点挖开（按下后等抬手），**按住 380ms 抢下这一格插旗**；拖开则取消 |
| 模式段控件 / `F` | 挖开 ⇄ 插旗 |
| 方向键 | **只移动光标**，空格/回车才落子 |
| `Z` / `Y` / `H` / `Esc` | 撤销 / 重做 / 求助 / 回首页（求助会记进成绩） |
| 线索推满 | 该数字剩余的未知格自动补旗（可在设置里关掉，关掉后**真的**由你自己插） |

五档难度，全部由求解器实测分数定档（下表是 `npm run balance` 每档 3 000 候选的实测）：

| 档 | 盘面 · 雷数 | 难度带 | 入选率 | 出题代价 | 特征 |
|---|---|---|---|---|---|
| 新兵 | 9×9 · 10 | 32 – 46 | 82.3 % | 2.5 次 / 0.1 ms | 九宫格里练手感 |
| 老兵 | 12×12 · 22 | 54 – 75 | 60.4 % | 3.2 次 / 0.3 ms | 成排推进，一次开花一大片 |
| 工兵 | 16×16 · 40 | 77 – 101 | 54.6 % | 3.4 次 / 0.5 ms | 要靠两条线索相减 |
| 排雷手 | 24×16 · 70 | 134 – 164 | 24.9 % | 7.1 次 / 2.0 ms | 长边推理，处处开花 |
| 突击队 | 30×16 · 99 | 194 – 230 | 5.0 % | 46.8 次 / 16.4 ms | 密布的雷区，一步看三格 |

**每日雷区**：按日期播种，五档轮转，同一天所有人拿到同一片雷区；连续天数计入 streak。
**成绩**：每档记最佳时间，判优顺序是 `求助少 → 步数少 → 用时短`——靠六次求助刷出来的"最快"没有意义。

## 为什么能保证"不用猜"

普通扫雷的做法是先随机布雷再看运气，于是"有解但人推不出"的盘遍地都是，玩家只能赌。
本作反过来：**用求解器当准入门**。

1. `rng.js` 从种子派生两层随机数，`generate.js` 挑一格作为开局格，并把**它的周围八格划为禁区**——
   所以"首次点击必安全"不是事后补救，而是布雷之前就写死的约束。
2. `layMines()` 在禁区外布雷，`field.js` 算出每格邻雷数与八邻接表。
3. `solver.js` 从开局格出发反复扫全盘，只有三条规则：
   - **单线索**：某个数字的未知邻居数正好等于它的雷数 ⇒ 全是雷；雷数已凑满 ⇒ 剩下的全安全；
   - **两数相减**：两个相邻数字的未知集是包含关系时，把差集减出来（1-2-1、2-2、贴墙推理都在这一类里）；
   - **雷数总账**：全局剩余雷数只剩最后一个容身之处时，账本本身就成了线索。
4. 只有 **每一个安全格都被翻开** 的候选盘才允许上线；差一格都不发。
5. `grade()` 的分数全部来自求解过程：3BV（完美玩家最少点击数，**用 `flood` 本体量**，所以不会和
   "一次点击实际开多少格"脱节）、pass 轮数、最长跨度、是否用到了相减/总账、雷密度。
   难度带就是这张分位表的四分位区间。

求解器自己也要被证明可靠，而且是**两条独立的路**互相指认：

- `npm test` 把每档 25 局（共 125 局）交给 `solve()`，再拿真实雷图逐格复核——翻开过雷、
  还剩安全格没开、宣布的雷数比盘上多，任何一条都直接判失败；
- 同一份测试再把每档 8 局交给 `nextHint()` **一步一步**地走，动作全部经过 `Game` 的真实规则层
  （dig / flood / chord / 自动插旗 / 胜负判定）。批量求解器和单步推荐器是两段不同的代码，
  规则层又是第三个来源——三者同时说"能推到底"，才叫证据；求解器有 bug 会当场红。
- `npm run balance` 末尾的 `solver cross-check` 再把分数分布的五个探针档各挑一局重放一遍。

## 求助的正确性，比"给个答案"更难

`nextHint()` 先把**你已经插下的旗当作已知事实**送进约束里（否则每插一面旗都会让下一次求助变弱），
再把每条建议拿去和真实雷图对账：

- 结论与雷图相符 ⇒ 给出这一步，并说明用的是哪条规则、钉在第几行第几列；
- 结论与雷图矛盾 ⇒ 说明**你的某面旗插错了**。此时它不会把你送上雷，而是改成"拔掉这几面旗"，
  并且真的替你拔掉（`verify hint`：错误旗被点名数 = 被拔掉数）。

开局那一格是**免费**的一步：它是规则保证安全的格，不是你漏掉的推理，所以不计入求助数。

## 反馈与无障碍

一次有效操作至少三条反馈通道：格子缩放脉冲 + 顶部雷数/进度条变化 + 合成音 +（移动端）触觉；
开花与和弦各有独立音效。错误不是弹窗，是**一句指出坐标的拒绝**，而且无效操作不计步数、不进撤销栈。

- 动效开关 = `prefers-reduced-motion` **与**游戏内开关的并集，任一开启即降级为无脉冲/无扫光。
- 所有颜色、间距、圆角、时长来自 `js/theme.js` 一处，`applyThemeVars()` 注入成 CSS 变量，
  样式表和 canvas 共用同一份令牌；视图里不留裸 hex 与裸像素尺寸。
- 格子尺寸下限 17px：再小数字和雷就是同一团糊。30 宽的盘在手机上**宁可横向滚动**也不缩到看不清。
- 触觉与音频都走 `navigator.userActivation` 真值判断：合成事件骗不过浏览器，也不该拿它当"用户已交互"。

## 验证矩阵（承诺 → 断在哪）

| 承诺 | 断在哪 |
|---|---|
| 每局可纯逻辑推到底 | `npm test`（125 盘逐格复核 + 40 盘只吃提示走真实规则通关）、`verify gen`（每档 3 盘 `stuckSafe === 0`） |
| 首次点击一定安全 | `verify engine`：逐格检查开局格的八邻无雷；`verify play`：挖别的格一律拒绝 |
| 难度带是真测出来的 | `verify gen` + `npm test`：命中率、每盘尝试次数上限、**五档分数带互不重叠** |
| 提示永不把你送上雷 | `verify hint`：三档全程只吃提示，逐格比对建议与真实雷图 |
| 提示只给可推导的格 | `verify hint`：只吃提示也能清空整盘（trainee / scout / commando 三档） |
| 提示解释规则并指出坐标 | `verify hint`：每条文案必须含 `N行M列` |
| 插错的旗被指出并拔掉 | `verify hint`：点名数 = 拔除数，且全程 0 次致命提示 |
| 一次开花 = 一步撤销 | `verify play`：一次 dig 翻开整片 ⇒ 1 步、1 条历史、1 次撤销全收回 |
| 撤销带走自动插的旗 | `verify play`（撤销后旗数归零，且**步数不退还**：退还就能靠撤销/重做刷出 0 步纪录） |
| 旗不够 / 旗过多都拒绝和弦 | `verify play`：先超插拒绝、拔掉后正好开花 |
| 挖自己的旗被拒 | `verify play` + `verify layout`（真实 PointerEvent 走 canvas） |
| 刷新不丢进度，也不丢代价 | `verify save` + `verify resume`：存档带 originSeed、RLE 盘面、用时、**步数与求助数** |
| 记录判优顺序 | `verify save`：更慢但少用求助算新纪录，反之不算 |
| 布局随容器收缩、真的画出来 | `verify layout`：480 格 `hitTest` 逐格往返、DPR 后备缓冲、canvas 像素采样 |

## 未实现（不是路线图，是缺口）

- 求助一次只给**一步**，没有"自动解到卡住为止"的托管模式（`solveWithLogic` 只存在于测试里）。
- 布雷是纯随机 + 过滤，没有"故意造一个需要相减的形"的目标生成，所以难题靠量堆而不是靠设计。
- 只有中文文案，没有 i18n。
- 没有云存档、没有排行榜、没有多设备同步——数据只在本机 `localStorage` 的一个键里。
- 桌面端是单栏布局的 Electron 壳，没有为宽屏做多栏重排。
- 键盘可达但没有完整屏幕阅读器叙述层（`aria-live` 只覆盖状态行）。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高。
- **钉住两个数**：`EXPECT_CHECKS=31`（R 段实际检查的路径条数）与 `EXPECT_ROWS=49`
  （这一次跑的断言条数）。没改页面却掉了，说明解析断了；删掉一张图标会同时少一条 R10 与那张的
  P1/P2，所以两个数一起钉，rows 能漂就是闸在缩水的信号。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`31`、rows 仍然 `49`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑，所以页面改了、仓与仓不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；把它们接进本仓
那条浏览器 one-shot（`tools/verify.sh`）还欠着——那道脚本的腿名单与条数钉是每个仓自己的形状。
